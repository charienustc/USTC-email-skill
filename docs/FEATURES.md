# 能力清单与使用条件

核对日期：2026-10-07，对应 `dist/ustc-mail/package.json` 的 1.1.0。

## 能力

| | 能力 | 说明 | 条件 |
| --- | --- | --- | --- |
| 📬 | **列出邮件** | 最新 N 封的信封：发件人、主题、日期、已读状态、大小、有无附件 | 无 |
| 🔎 | **搜索头部** | 主题 / 发件人 / 收件人子串、收到日期区间、未读筛选，条件之间是 AND | 至少给一个条件 |
| 📝 | **搜索正文** | `--body` 搜正文；`--anywhere` 一次搜"主题或正文" | 子串匹配，不是语义检索 |
| 📖 | **读取正文** | 按 `uid` 读出正文与附件清单 | 需要 `uid`，来自 list 或 search |
| 📚 | **一次读多封** | 最多 20 个 `uid`，**一条连接**读完；找不到的 uid 单独列出，不影响其余 | 单封正文上限 20000 字符，多封默认 2000 |
| 📎 | **附件清单** | 文件名、类型、大小 | **只列名字，内容要 `attach`** |
| 💾 | **保存附件** | 写进指定目录，文件名重建成安全名 | **会写磁盘**；见下 |
| ⚡ | **正文片段** | `--preview` 给整个列表附正文开头，在已开的连接里完成 | 只用于粗筛 |
| 🌐 | **中文** | 主题、发件人、正文的 UTF-8 / GBK / Big5 解码；中文搜索用 `CHARSET UTF-8` | 依赖 Node 的完整 ICU 构建 |
| 🗂️ | **文件夹** | `INBOX`、`已发送`、`草稿箱`、`已删除`、`垃圾邮件` 等，中文名自动转 modified UTF-7 | 名字须与服务器一致 |
| 🧾 | **HTML 正文** | 只有 HTML 的邮件自动转纯文本 | 转换是粗略的 |
| 🔑 | **凭据** | 系统钥匙串优先，无钥匙串时用权限 600 的文件 | 见下 |
| 🖥️ | **跨平台** | Windows / macOS / Linux，同一份代码 | 需要 Node 18+ |

## 使用条件

**运行环境**

- Node.js 18 或更高，且是**带完整 ICU 的构建**（官方发行版默认满足）。自编译的 small-icu 版本无法解码 GBK 中文邮件。
- 网络可达 `mail.ustc.edu.cn:993`。只走 IMAP over TLS，**明文 143 未启用**。
- 学校账号需在邮箱设置里**开启 IMAP 服务**；若开了二次验证，口令要填邮箱设置里生成的**客户端授权码**，不是登录密码。

**凭据**

按顺序查找：插件配置 → 环境变量 → 当前系统的钥匙串 → `~/.dsh/ustc-mail-credentials.json`（权限 600）。

| 平台 | 钥匙串 | 查看或删除 |
| --- | --- | --- |
| Windows | 凭据管理器，条目名 `USTC-Mail` | 控制面板 → 凭据管理器 → Windows 凭据 |
| macOS | 钥匙串，服务名 `USTC-Mail` | 钥匙串访问.app |
| Linux | Secret Service，需要 `secret-tool` | GNOME/KDE 的「密码与密钥」 |
| 任意 | 兜底文件 | 直接编辑或删除 |

没有钥匙串不会导致失败——那一层探测不到就跳过，直接用文件。**命令在、服务不在**（headless Linux 上很常见）也一样：读会静默回退，**写会在失败时退回文件并说明原因**，不会让你白输一遍授权码。

**环境变量是临时覆盖用的，不建议长期保存**：它会被每个子进程继承，比文件传播得更广。

## 已知限制

- **不能发信、标记已读、移动、删除**。这是设计约束，不是未完成项。（`attach` 只往**本地磁盘**写，邮箱本身一个字都不动。）
- **每次调用都是一条新的 IMAP 连接**（含 TLS 握手，约 0.3–3 秒，与邮件大小无关）。所以粗筛要用 `--preview`。
- **搜索是子串匹配**，不是语义检索：搜"报销"找不到只写了"报账"的邮件；没有正则，也没有给用户拼逻辑的 `NOT`。`--anywhere` 内部的 `OR` 是固定的"主题或正文"，不是通用布尔检索。
- **`--from` / `--to` 匹配整个地址头**（含显示名），所以 `--from 某部门` 会连同显示名一起命中。
- **日期按服务器的内部日期（收到时间）算**，`--before` 不含当天。服务器时区与本地不一致时，边界日可能差一天。
- **`read` 一次最多 20 封**，一条连接读完。正文**单封默认截断到 20000 字符、多封默认 2000**；单次取正文的编码字节上限 2 MiB。
- **`--preview` 的片段压成一行**，且只取 `preview × 6 + 1024` 字节（上限 64 KiB）的原始载荷，所以 HTML 邮件或高比例转义的邮件，片段可能短于请求的字符数。
- **HTML 转纯文本会丢样式、表格布局和图片**，只保留可读文字。
- **`hasAttachments` 来自解析出的 BODYSTRUCTURE**；解析失败时退回文本扫描，只有 `name=` 参数而没有处置声明的部分可能漏判。
- **`list` / `search` 每次最多返回 100 封**；`matched` 是全量命中数，`returned` 是本次返回数。
- **macOS 保存凭据的一瞬间，授权码对进程列表可见**（`security` 命令的固有妥协）。Linux 没有这个问题。
- 钥匙串与 600 文件都**挡不住以你的身份运行的程序**，只能挡住离线副本和同机器的其他账户。

## 明确不做的事

| 不做的 | 原因 |
| --- | --- |
| 标记已读 | 只读承诺。`BODY.PEEK` 与 `EXAMINE` 在协议层保证 |
| 删除、移动、发送 | 同上；没有 SMTP 实现 |
| 把附件内容读进对话 | 二进制塞进上下文毫无用处，还绕过了"落盘需要用户知情"。要内容就 `attach` |
| 保存登录密码 | 只接受客户端授权码，且只进钥匙串 |

## 搜索正文

`--body` 只看正文，`--anywhere` 一次搜"主题或正文"。两者都是**子串匹配**，实测**与搜头部同一量级**（几十毫秒），所以不需要为了省时间而回避正文。

**`--anywhere` 内部分别搜主题和正文再取并集**，用的是 IMAP 的 `OR`。真机上验证过它确实是并集而不是拼接：某个词 `--subject` 40 封、`--body` 4 封、`--anywhere` **42 封**——说明有 2 封同时命中，没有重复计数。

**为什么不用 IMAP 的 `TEXT` 键**（"搜所有内容"）：测得它要 **4.7–6 秒**，比 `BODY` 慢约一百倍且不缓存；更要紧的是**结果不可信**——同一个词，`SUBJECT` 19 封、`BODY` 48 封，而 `TEXT` 只有 36 封，**漏掉并集里的 14 封、另有 2 封在并集之外**。既慢又不准，所以这个客户端**一个字节的 `TEXT` 都不发**。

## 保存附件

`attach` 是**唯一会写磁盘**的命令：它把附件取出来写进本地目录，**邮箱本身一个字都不动**——不移除附件、不改已读状态、不删除邮件。

| 约束 | 值 |
| --- | --- |
| 单个附件上限 | 25 MiB（解码后） |
| 单次调用总量上限 | 60 MiB |
| 单次最多保存 | 10 个附件 |
| 默认目录 | 工作目录下的 `ustc-mail-attachments/` |

超限的附件**不会被静默丢弃**——会在结果里列出来并说明原因。

**文件名一律重建，不信任。** 附件名由发件人决定，可能包含任何东西：

| 邮件里声明的名字 | 写出的名字 | 为什么 |
| --- | --- | --- |
| `../../.ssh/id_rsa` | `id_rsa` | 只取最后一段，路径穿越失效 |
| `C:\Windows\System32\evil.dll` | `evil.dll` | 同上，两种分隔符都处理 |
| `/etc/passwd` | `passwd` | 同上 |
| `CON`、`NUL.pdf` | `_CON`、`_NUL.pdf` | Windows 把它们当设备，不是文件 |
| `....hidden` | `hidden` | 前导点会变成隐藏文件 |
| `a<b>c:d"e\|f?g*h.txt` | `a_b_c_d_e_f_g_h.txt` | Windows 非法字符 |
| 300 字符的长名 | 截断到 120 字符，保留扩展名 | 文件系统长度限制 |

同名文件不会覆盖，第二份写成 `名字-1.xls`。写出前还会再校验一次目标路径确实落在指定目录内。

**邮件里的原始文件名属于外部数据**，报告给用户时应当使用**实际写出的文件名**。
